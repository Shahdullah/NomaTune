## v1.3.21 — anonymous playback: the auth-state difference from ArchiveTune

The v1.3.20 rotation worked, but rotation was never the whole story: both anonymous clients
came back with *"Please sign in"*. Comparing the live bundle against ArchiveTune's playback
stack found two places where NomaTune had drifted from ArchiveTune, both in how the saved
auth state is read. Both are now ArchiveTune's code, verbatim.

### 1. `PlaybackAuthPreferences.toPlaybackAuthState()` — restored to ArchiveTune's version

NomaTune was reading `poTokenGvs` / `poTokenPlayer` / `webClientPoTokenEnabled` straight out of
DataStore. Those keys can hold tokens minted by an *older* build (or by a WebView whose visitor
identity no longer exists), and replaying such a token turns every anonymous request into
"Please sign in". ArchiveTune only trusts the legacy `PoTokenKey` and derives the flag from it:

```kotlin
val legacyPoToken = this[PoTokenKey]?.trim()?.takeIf { it.isNotEmpty() && !it.equals("null", ignoreCase = true) }
return PlaybackAuthState(
    cookie = this[InnerTubeCookieKey],
    visitorData = this[VisitorDataKey],
    dataSyncId = this[DataSyncIdKey],
    poToken = legacyPoToken,
    poTokenGvs = null,
    poTokenGvsSession = null,
    poTokenPlayer = null,
    webClientPoTokenEnabled = legacyPoToken != null,
).normalized()
```

### 2. `hasCompleteYouTubeLoginCookies()` — ArchiveTune's function is back in core

`YoutubeiStreamRepository` was using a local helper that only looked for `SAPISID`-family
cookies and ignored `LOGIN_INFO`. ArchiveTune's core function (now restored) requires
`LOGIN_INFO` **and** a SAPISID-family cookie, so a half-expired login is treated as invalid
instead of being sent to YouTube as a broken account context. The local duplicate was deleted
and the file calls core's function again, as ArchiveTune does.

### What is intentionally *not* copied

ArchiveTune's `NetworkGatekeeper` OkHttp interceptor is still absent — it fails every request
until the build verifies itself against Rukamori's servers, which is the one thing that cannot
travel into a fork.

### Verification

Live bundle, anonymous, no cookie — same request the app makes:

| case | result |
|---|---|
| request **with** a valid visitor identity | resolves, `itag=140`, range probe **HTTP 206** |
| request with **no** visitor identity | `VISIONOS: Sign in to confirm you're not a bot` — the exact on-device text |

So when the anonymous path has no usable visitor identity, the failure is identical to yours.
This build removes the two ways NomaTune could poison that identity. If the red screen comes
back, the message will say which client and which reason, and the next step is the visitor
identity itself.
