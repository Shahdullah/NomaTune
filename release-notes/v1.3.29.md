# NomaTune v1.3.29

## Signed-out playback — the actual cause

This was a regression I introduced, not a YouTube change. Since v1.3.26 NomaTune wrapped the anonymous request in a
"strip the identity" step that ArchiveTune does not have: `visitorData`, the session PoToken and the video PoToken
were removed before the request went out (in the JS resolver from v1.3.28, and in `YoutubeiStreamRepository` too).

YouTube's anonymous player needs that identity. Removing it turned "a couple of tracks fail signed out" into "nothing
plays unless you sign in" — which is exactly what happened.

ArchiveTune never strips anything; it passes the request through untouched and plays signed out fine. NomaTune now
does the same. Verified by replaying the same signed-out request through both shipped resolvers: the outgoing
`/player` request is now **identical** — same client (MWEB 2.20260205.04.01), same `visitorData`, same PoToken, same
headers.

Removed: `stripPoTokens`, `anonymousWithoutIdentity`, the retry wrapper around `resolve()` and its two helpers.

## Navigation bar

The tab list had a fourth entry ArchiveTune does not have (`MoodAndGenres`). The dock lays items out with equal weight
inside a fixed width budget, so the extra entry squeezed every item and pushed the last one out of the bar. It is now
exactly ArchiveTune's list: **Home, Search, Library**. Mood & Genres is still reachable from Home and Explore.

Dock metrics also matched to ArchiveTune: bar height 78dp (was aliased to the 72dp toolbar height), bottom padding
10dp.
