# NomaTune v1.3.26

## Playback without an account — the actual cause

A signed-out device kept a residual `APISID` cookie in the playback auth state. NomaTune's login-cookie list
included `APISID`; ArchiveTune's does not. So NomaTune decided "this user is signed in":

- `hasLoginCookie` became `true`, so the dead cookie was forwarded to YouTube,
- no `SAPISID` was present, so no `SAPISIDHASH` `Authorization` header could be generated,
- YouTube answered `YoutubeiException: Please sign in` for the only anonymous client (`MWEB`),
- and the app reported `No stream available`.

The login-cookie list is now identical to ArchiveTune's (`SAPISID`, `__Secure-3PAPISID`, `__Secure-1PAPISID`).
With `APISID` no longer counted as a login, a signed-out device reports itself as anonymous, sends no cookie,
and resolves the stream the way ArchiveTune does.

Verified against YouTube from this sandbox: a dead cookie reproduces `Please sign in` exactly; no cookie plays
`itag=140`.

## Notes

- Resolver is still ArchiveTune's, copied verbatim (single `MWEB` client).
- If the app still refuses, sign out and back in once: the stale value is cached in the auth state until it is rewritten.
