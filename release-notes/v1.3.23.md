## v1.3.23 — native-client fallback for anonymous playback

Both anonymous clients (MWEB, VISIONOS) are web clients: YouTube only gives them formats
when the request carries a PoToken, and without a valid one they answer **"Please sign in"**.
ArchiveTune has the same two web clients in its resolver, but its app-level stream fallback
chain (`STREAM_FALLBACK_CLIENTS`) also contains **native** clients, which YouTube serves
without any token. NomaTune's own fallback chain exists too — it just was never reached,
because the youtubei.js resolver answered first and threw.

### What changed

The anonymous client rotation now ends with two native clients:

```js
: [ANONYMOUS_CLIENT, ANONYMOUS_DIRECT_CLIENT, "ANDROID_VR", "IOS"];
```

`MWEB → VISIONOS → ANDROID_VR → IOS`, still with the one tokenless retry from v1.3.20.
Nothing else changed — the ArchiveTune-verbatim auth-state fixes from v1.3.21/22 stay.

### Verification

Same bundle, same request, forcing the two web clients to answer `LOGIN_REQUIRED: Please sign in`
(the exact text on the phone):

| scenario | clients tried | result |
|---|---|---|
| all clients allowed | `MWEB` | plays `itag=140`, range probe **HTTP 206** |
| MWEB + VISIONOS refused ("Please sign in") | `MWEB → VISIONOS → ANDROID_VR → iOS` | **plays `itag=140`, range probe HTTP 206** |

Direct API check for the same video and visitor identity: `MWEB` = `UNPLAYABLE`, `VISIONOS` = OK,
`ANDROID_VR` = OK (4 audio formats), `IOS` = OK — the native clients are consistently served.
