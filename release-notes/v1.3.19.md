NomaTune 1.3.19 fixes the remaining "No stream available" tracks by restoring the second anonymous playback client that was lost in the fork.

---

## ✨ Highlights

### 🎧 The Missing Anonymous Client

- **Fixed songs that failed with "No stream available" while signed out** — the ones that played fine after signing in
- Anonymous playback only ever tried **one** YouTube client. When YouTube answers that client with SABR-only playback — a format the app cannot download as a file — playback died immediately instead of asking the next client
- NomaTune now tries a **second, direct-stream client** when the first one has nothing downloadable. That client returns ready-to-play links, so no deciphering step is needed
- Signing in used to "fix" these tracks because a signed-in request is sent as a different client which still returns normal formats — the anonymous path now has the same coverage
- Failure messages now say **why**: "only SABR streams offered" instead of a generic "No direct audio format", so a genuinely restricted track is distinguishable from a fixable one

### 🔑 Video-Bound Playback Tokens

- Fixed the player silently falling back to a **generic** token even when a token minted specifically for that video was available
- That fallback is what produced HTTP 403 on some tracks. The video ID now reaches token resolution, so the correct video-bound token is used
- Network and timeout failures still stop the rotation immediately — rotating clients on a flaky connection only made things slower

---

## 🐛 Bug Fixes

### Playback

- Restored anonymous client rotation (first client → direct client) for SABR-only responses
- Fixed video-bound PoToken never being selected
- Fixed anonymous failures being reported without the SABR reason
