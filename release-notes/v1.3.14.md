NomaTune 1.3.14 is a playback reliability release. It fixes the false **“Sign in to YouTube Music”** wall that stopped songs from streaming while signed out, so signed-out playback works again — no account needed.

---

## ✨ Highlights

### 🎧 Signed-Out Playback Works Again

- **Fixed M83 — “Midnight City” and the rest of the catalogue failing with `Code: 2000` / `Cause: qxa: Please sign in`**
- Anonymous streaming no longer depends on a single YouTube client. NomaTune now walks a fallback chain (**MWEB → IOS → ANDROID_VR → ANDROID**) and keeps the first client that returns a *real*, decipherable audio format
- Explained: YouTube often answers the mobile web client with `playabilityStatus: OK` but with audio formats that carry **no stream URL at all** (server-Abr only). That case used to surface as “No direct audio format” and then as the sign-in dialog. Now the next client is tried automatically, so playback just starts
- `LOGIN_REQUIRED` / `TIMEOUT` failures still short-circuit immediately instead of burning through clients, and if every client is exhausted the original error is preserved for accurate diagnostics

### 🔓 “Sign In” Is Optional Again

- Signed-out users are never told they *must* sign in. The failure sheet is now titled **“Playback unavailable”** and explains that Retry usually works without an account
- **Retry** is offered first; the optional **Login** action appears only for content that genuinely needs an account (age-restricted, private, members-only)
- Playback resolution no longer converts a recoverable stream failure into a hard login wall: `LoginRequiredForPlaybackException` is now part of the fallback set, so the multi-client YouTube recovery path runs first

### 🧩 Build & Diagnostics Hardening

- Release builds are no longer R8-obfuscated (`-dontobfuscate` + `SourceFile,LineNumberTable`). Reflective and `@JavascriptInterface` WebView bridges (**BotGuardBridge**, **Android**) keep their names, and exception classes stay readable — no more `qxa` in error dialogs
- Added explicit keeps for `@android.webkit.JavascriptInterface` members, `utils.potoken.**` and `morideobfuscator.youtubei.**`
- The packaged `youtubei.js` runtime (`youtubei.bundle.js`) was rebuilt from source, so the shipped asset actually contains these fixes

### 🔐 Seamless Updates, Always

- Every APK is signed and verified against the **permanent NomaTune release key** (`SHA-256 17:C1:E0:EB:…:84:41`) — installs cleanly over your existing app, no uninstall required

---

## 🐛 Stability & Bug Fixes

### Playback

- Fixed false `Sign in to YouTube Music` errors during anonymous playback
- Fixed `No direct audio format` failures caused by server-Abr-only responses from the mobile web client
- Improved stream recovery: primary resolver failures now fall through to the client-rotation fallback instead of aborting

### Diagnostics

- Readable stack traces in release builds, so playback reports are actionable again
- Release notes are now versioned in `release-notes/` and published automatically with each release
