# NomaTune v1.3.30

## Dock: real ArchiveTune port

`FloatingNavigationToolbar` was already byte-identical to ArchiveTune's, but the call site in `MainActivity` was not.
That is why the bar still looked wrong. Four things were missing:

- **`miniPlayerProximityProvider` was a hardcoded `{ 0f }`.** ArchiveTune feeds it a real value derived from the
  mini-player sheet position and the animating nav height. Without it the labels never collapse or expand, they just
  truncate. This is ported verbatim now.
- **No `.height(navVisibleHeight)`** on the dock modifier.
- **No `onSearchItemDoubleClick`** — tapping Search twice now switches to online search and opens it.
- **No sheet/collapse handling on tab press** — tapping a tab while the player sheet is expanded now collapses it
  first, instead of navigating underneath it.

## Playback signed out

The real culprit for the signed-out failure: NomaTune has a PoToken settings screen that ArchiveTune does not, and
`Preferences.toPlaybackAuthState()` set

```kotlin
webClientPoTokenEnabled = legacyPoToken != null
```

with no regard for whether you were signed in. A stored token therefore left web PoTokens enabled **forever**, so
every signed-out request carried a PoToken minted for a different session — which is exactly the state your error
dialog reported (`signedIn=false,visitor=true,...,poToken=true,sessionPoToken=true,webPoTokens=true`). YouTube answers
"Please sign in" for that, on every client, no matter how many times the request is retried.

PoTokens are now only ever used alongside the login cookie they were minted for.
