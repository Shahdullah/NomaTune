NomaTune 1.3.17 fixes two things you hit in a row: songs that refused to play signed out, and an Update button that could look like it did nothing at all.

---

## ✨ Highlights

### 🎧 Signed-Out Playback Is Genuinely Fixed

- **Songs like “Midnight City” now play without signing in.** The anonymous playback fallback stopped early: one of the YouTube clients it tries answers with a bot check ("Sign in to confirm you’re not a bot"), and NomaTune treated that as “this track needs an account” — even though the very next client streams it fine
- A single client asking for a sign-in no longer ends the attempt. NomaTune keeps going through the other anonymous clients and only reports a login problem if **every one** of them asks for it
- Reordered the clients by reliability, so the ones that actually serve audio are tried first instead of the one that usually answers with a bot check
- Result: playback resolves anonymously again for ordinary catalogue tracks, with no account needed

### 🔘 The Update Button Always Tells You What Happened

- **The Update button in the update sheet now shows a progress bar while it downloads** and prints the actual reason if the download could not start, instead of silently doing nothing
- The update button on the Account screen shows a short "Downloading…" message and reports a failure instead of swallowing it
- Fixed the number-one cause of the "nothing happens" feeling: every error from the download and the package-installer hand-off used to be discarded by an empty `try/catch`
- Tapping the notification still lands on the in-app **Updates** screen (fixed in 1.3.16)
- Update cache files no longer carry a leftover third-party name

---

## 🐛 Bug Fixes

### Playback

- Fixed the anonymous fallback chain aborting on the first client that answers with a bot check
- Fixed "Confirm playback in YouTube Music, then return to NomaTune" being shown for tracks that are freely streamable
- Reordered anonymous clients: the reliable ones are tried before the bot-check-prone one

### Updater

- Fixed the update sheet's Update button discarding all download errors
- Fixed the Account screen's update shortcut discarding all download errors
- Added a download progress bar to the update sheet
- Renamed leftover update cache file names

## 🧾 Technical Summary

| Area | Change |
| --- | --- |
| `youtubei` runtime | `resolveAnonymousWithFallbacks` no longer aborts on `LOGIN_REQUIRED`; it remembers the failure and keeps trying, only failing when every client demands a sign-in |
| `youtubei` runtime | `ANONYMOUS_CLIENT_FALLBACKS` reordered to `IOS, ANDROID, ANDROID_VR` |
| `MainActivity` | Update sheet: progress state, failure text, no empty catch |
| `AccountSettings` | Snackbar host; "Downloading…" and failure feedback |
| `AppUpdateInstaller` | Cache file names updated |

---

## 🧪 How This Was Verified

The anonymous client matrix was measured directly against YouTube for the reported track:

| client | answer |
| --- | --- |
| `MWEB` | `UNPLAYABLE` — page reload |
| `IOS` | **OK** — audio formats |
| `ANDROID_VR` | `LOGIN_REQUIRED` — bot check |
| `ANDROID` | **OK** — audio formats |

Before the fix `ANDROID_VR` short-circuited the whole chain. After the fix: 9/9 resolutions succeeded with a live `206` range probe on the returned CDN URL.
