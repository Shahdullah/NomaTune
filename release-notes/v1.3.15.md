NomaTune 1.3.15 fixes the startup crash introduced in 1.3.14 and makes updating work entirely inside the app — the update notification now downloads and installs the new version instead of opening a web page.

---

## ✨ Highlights

### 🛠️ Startup Crash Fixed

- **Fixed the crash on launch after updating to 1.3.14** — `java.lang.VerifyError` in the artwork loader, which made the app close immediately on some devices (Android 15 / MediaTek in particular)
- Root cause: the release optimizer compiled one of the image-loading lambdas into invalid bytecode. That code path is now built in a clearer, optimizer-safe form, and the optimizer pass responsible for it is disabled across the whole build
- Added protection for Kotlin coroutine state machines so this class of crash cannot silently come back in a future release
- Release builds stay readable (`SourceFile`, `LineNumberTable`), so if anything does go wrong the report points at a real class and line

### ⬇️ Updates Install In-App

- **The update notification now downloads and installs the new version by itself** — tapping **Download** fetches the APK and opens the system installer. No more being sent to a browser page on github.com
- Fixed the update link so it always points at the **direct APK** for your exact device build, never the release page. If the newest version tag has not been fetched yet, NomaTune looks it up on the spot instead of falling back to a web page
- The **Update** button in Settings, the update bottom sheet and the update banner on the Account screen all run the same in-app download+install flow, with live progress
- A small progress notification appears while downloading and reports a clear failure message if the download could not be completed
- Added the install-packages permission so the system installer can be launched directly

### 🎧 Playback (From 1.3.14, Now Reaching You)

- Signed-out playback works again: songs stream without signing in to YouTube Music
- Anonymous streaming no longer depends on a single YouTube client — if one client returns formats without a usable stream URL, the next client is tried automatically
- “Sign in to YouTube Music” is gone as a forced step: the failure sheet is now **“Playback unavailable”**, offers **Retry** first, and only suggests signing in for age-restricted, private or members-only tracks

### 🔐 Seamless Updates, Always

- Every APK is signed and verified against the **permanent NomaTune release key** — installs cleanly over your existing app, no uninstall required

---

## 🐛 Stability & Bug Fixes

### Updater

- Fixed “Download” opening the GitHub release page instead of downloading
- Fixed the update URL falling back to a web page when the latest tag had not been cached yet
- Fixed downloads that were left behind in the cache between attempts
- Added a fallback for release assets that arrive as a zip bundle instead of a plain APK

### Startup

- Fixed the `VerifyError` crash on launch
- Hardened coroutine and JSON bytecode against optimizer mis-compilation

### Playback

- Anonymous stream resolution retries across multiple clients before giving up
- Signed-out playback failures no longer demand a login

## 🧾 Technical Summary

| Area | Change |
| --- | --- |
| `App.kt` | `newImageLoader` no longer builds a chained coroutine lambda that mis-dexed |
| `proguard-rules.pro` | `-dontoptimize`, coroutine/continuation/JSON keeps |
| `UpdateApkFetcher.kt` | Shared download → verify APK → launch installer helper |
| `UpdateInstallReceiver.kt` | Notification action downloads and installs in-app |
| `Updater.kt` | `getLatestDownloadUrl` always returns a direct APK asset URL |
| `UpdateNotificationManager.kt` | Download action is a broadcast, not a browser intent |
| `MainActivity`, `UpdateScreen`, `AccountSettings` | All update buttons use the in-app installer |
| `AndroidManifest.xml` | `REQUEST_INSTALL_PACKAGES`, `UpdateInstallReceiver` |
