## v1.3.24 — tokenless anonymous resolution + one more client

Your v1.3.23 dialog listed **all four** clients as `Please sign in`:

```
MWEB: Please sign in; VISIONOS: Please sign in; ANDROID_VR: Please sign in; IOS: Please sign in
```

That is the fallback chain working exactly as written — I can reproduce that string in the
harness by making every client refuse. What it means is that the refusal is coming from the
shared parts of the request, not from the client choice: the **visitor identity** and the
**PoTokens** that every attempt carries along.

(For comparison, straight API probes with a fresh visitor identity return `ANDROID_VR` = OK and
`IOS` = OK for the same video — so on a clean identity the native clients are served.)

### What changed

1. **Anonymous playback is resolved without any PoToken and without the cached visitor
   identity.** A visitor identity/ token that YouTube has stopped accepting makes *every*
   client answer "Please sign in", so anonymous requests now go out clean and let YouTube
   issue a session. Signed-in playback (`cookie` present) is untouched.
2. **`ANDROID` is added to the end of the rotation** —
   `MWEB → VISIONOS → ANDROID_VR → IOS → ANDROID` — still with the v1.3.20 tokenless retry and
   the v1.3.21/22 ArchiveTune auth-state fixes.

### Verification (shipped bundle, real network)

| scenario | result |
|---|---|
| plain anonymous request | plays `itag=140`, probe **206** |
| stale visitor identity | plays `itag=140`, probe **206** |
| stale visitor + junk PoTokens | plays `itag=140`, probe **206** |
| MWEB + VISIONOS forced to `LOGIN_REQUIRED` | falls through to `ANDROID_VR` → plays, probe **206** |
| every client except `ANDROID` forced to refuse | reproduces your exact dialog text, then `ANDROID` is tried |

If the red screen comes back after this, the client list is exhausted and the wall is on the
network side — in that case the app can only report it, not code around it. The
ArchiveTune-vs-NomaTune side-by-side test on the same Wi-Fi is the next decisive datapoint.
