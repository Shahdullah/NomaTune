NomaTune 1.3.16 makes the update notification land where it should — tapping it now opens NomaTune's own **Updates** screen instead of a web page.

---

## ✨ Highlights

### 🔔 Update Notifications Stay In-App

- **Tapping an update notification now opens Settings → Updates inside NomaTune**, with the new version, the changelog and the **Update** button right there — no browser, no GitHub page
- Fixed the notification handing over a navigation route that the app never read, so the tap used to fall through and could end up on a web page. The route is now handled both when the app is launched cold and when it is already running
- The update **bottom sheet** opens by itself on top of the Updates screen, so the changelog is visible immediately
- The notification's **Download** action still downloads and installs in the background — and if a download ever fails, tapping that notification now opens the in-app Updates screen to retry, instead of going anywhere near a browser

### 🔁 Reopening Behaviour

- Update screens are opened with `launchSingleTop`, so tapping the notification twice no longer stacks duplicate screens on top of each other
- Fixed deep links and notification routes being ignored when NomaTune was already open in the background

### 🧱 Carried Over

- Startup crash from 1.3.14 stays fixed (`VerifyError` in the artwork loader)
- Signed-out playback keeps working — no account needed

---

## 🐛 Bug Fixes

### Notifications

- Fixed the update notification ignoring its in-app destination
- Fixed notification routes not being applied while the app was already running
- Fixed a failed update download leaving no way to retry from the notification

### Navigation

- Notification and deep-link routes now share one handler that always runs first
- No more duplicate Updates screens when the notification is tapped repeatedly

---

## 🧾 Technical Summary

| Area | Change |
| --- | --- |
| `MainActivity` | Reads the `navigate_to` extra in `handleIntent` (cold start **and** `onNewIntent`), navigates with `launchSingleTop` |
| `MainActivity` | New `EXTRA_NAVIGATE_TO` / `ROUTE_UPDATE_SETTINGS` constants |
| `UpdateNotificationManager` | Uses the shared route constants for its content intent |
| `UpdateInstallReceiver` | Failure notification points at the in-app Updates screen |
| `UpdateScreen` | Non-installer flavours report a failed hand-off instead of failing silently |
